Decomposing the Gain

An LLM edited two weight matrices of a small model and reportedly lifted its MATH-500 score from 7.9% to 48.1%. We asked how much of that gain you can get without editing anything.

JKUL · November 2026
Paper by Juan José Giraldo Márquez and Juan José Gómez · Read the paper (PDF) · Code and data

TL;DR

The edit is real. We reproduce it, and a random edit of the same size does almost nothing. But most of the gain does not need an edit: on MATH-500, turning thinking off with the full token limit reaches the same score. And the gain depends on the sampling temperature. At the temperature Qwen recommends, it falls from +43.5 to +11.0 points.

The loop

In thinking mode, Qwen3.5-0.8B often never stops. 92.2% of its responses use up all 32,768 tokens. It gets stuck repeating itself, and it never reaches an answer.

Here are real responses to the same problem. All three run at the same speed, so you can see which ones finish.

Real outputs from seed 0, sped up. Long stretches are skipped and marked in the text. The token count is estimated during playback, and the final count is exact.

How these were chosen: at seed 0, 30 of the 100 problems make the unedited model hit the limit while p50c and no-think, 32k both answer correctly. We picked the first three from that group because they are easy to read. The last two show failures and were picked by rule (lowest difficulty, then shortest cycle): 7 problems where p50c also hits the limit, and 12 where no-think, 32k finishes with a wrong answer.

We replicated it first

We rebuilt the published edit bit for bit from the authors' files, and ran it with their exact configuration. The unedited model scores 7.8% and p50c scores 51.2% on our 100 problems. Both are consistent with the reported 7.9% and 48.1%.

The gain of +43.5 points goes one way only. In 174 (problem, seed) pairs only the edited model is right, and in none only the unedited one. So everything below decomposes the same effect the original work reported.

Turn thinking off

The obvious knobs against repetition help only modestly: the best one, repetition_penalty 1.1, reaches 24.0%. Switching thinking off moves accuracy as much as the edit does.

With the full token limit, the unedited model without thinking scores 51.5%. That ties p50c at 51.2%: the paired difference is +0.2 points (CI −5.5 to +6.0). With the original authors' no-thinking profile it scores 45.2%, and that gap is not significant after correction.

In no-thinking mode the edit adds nothing on MATH: at 32k both models score 51.5%.

The gain from thinking-off comes from responses that used to loop, the same group where Sol Messing's audit located the edit's gain.

It isn't random

The edit is small: it changes two tensors by 8–11% of their norm, in 64 columns each, and it is effectively rank one. So could any change of that size break the loops?

No. A placebo with the same norm, tensors and columns, in a random direction, stays near the unedited model. The real edit is 40.0 points better on the same seeds. Its direction matters. This is the strongest point in favor of the original work.

The placebo is limited to two seeds, MATH only, and one kind of random direction.

Change one number

The original work ran at temperature 0.6. The Qwen model card recommends the same thinking configuration with one change: temperature 1.0. So we ran both models there, with four seeds.

On MATH, the gain falls from +43.5 to +11.0 points, because the edited model loops again: 64.2% of its responses hit the limit, against 29.2%. On GSM8K the gain is +13.8 points (CI +7.8 to +19.8), and the edited model's limit rate rises from 6.0% to 36.5%.

On IFEval the order reverses: the unedited model is 7.0 points above the edited one (CI +0.2 to +13.8). The interval nearly touches zero, so this is weak evidence that the edit hurts there, and firmer evidence that its advantage is gone. Looping does not explain that drop, since 1.0% of the edited model's responses hit the limit at both temperatures.

This does not make the edit wrong. It means that "7.9% → 48.1%" describes one configuration, not the model.

Cut the loop

A second cheap baseline keeps thinking on, as the model card suggests: watch the stream, and act when a loop appears. Retrying (A) helps little, reaching 13.0% on MATH. Cutting the loop and forcing an answer (B) reaches 34.0% on MATH and 57.0% on GSM8K. On MATH it costs 11,268 tokens per problem, about half of the edited model's 21,899.

It stays below the edit, by 17.0 points on MATH and 14.0 on GSM8K. Part of that gap is our own design: the forced answer has a cap, so B is a lower bound. The comparison is also asymmetric, because we gave loop handling only to the unedited model.

The cheapest way to stop the loops is also the cheapest to run. Mean tokens per response on MATH are 30,770 for the unedited model in thinking, 21,436 for p50c, 7,955 for no-think, 32k, and 3,388 for no-think, MIT sampling. We cannot measure the cost of finding the edit.

What's left

One part of the edit's benefit is not explained by any cheap baseline we tried: at temperature 0.6, p50c with thinking stays above the unedited model without thinking. At temperature 1.0, with 4 seeds, that residual disappears.

This residual belongs to the edit combined with thinking, not to the edit alone: with thinking off, p50c is no better than the unedited model. Whether it survives other sampling settings is the question most worth studying further.

What the original work got right

This decomposition is only possible because of how the work was published.

  • It published everything needed to check it: the edits, the code that applies them, the sampling configuration and the full logs.
  • The headline result replicates.
  • The edit is small and specific. It found a direction in weight space that matters.
  • It is not just "thinking off", and was not allowed to be. The editing prompt ruled that out, and the edit keeps the reasoning.
  • Its baseline is a reasonable one. We see no sign that it was chosen to look weak.

Our disagreement is about attribution, not about whether the edit works. Several controls here come from Sol Messing's public audit of the logs.

Limitations

  • Small, fixed problem sets. We use 100 problems per benchmark, where the original used 500 × 4.
  • Seeds are not independent samples, so p-values on pooled seeds are optimistic.
  • Exploratory analyses. This study was not preregistered. The second GSM8K subset and the model-card configuration were added after seeing results.
  • One seed for the unedited thinking baseline on GSM8K and IFEval, so comparing the edit's gain between temperatures on those benchmarks rests on that seed.
  • Loop handling is single-seed and asymmetric.
  • IFEval checker. We use lm-eval's checker, so our IFEval numbers are not comparable to the original ones.
  • Scope. One model and one failure mode. We did not run the "prompt without a hint" control.

The paper lists all of them in §12.
